## 🔍 Фундаментальные проблемы

### 1. API ограничения Mango Office

**Что можно через API:**
- ✅ Инициировать звонок (`commands/callback`)
- ✅ Получить баланс (`account/balance`)

**Что НЕЛЬЗЯ через API:**
- ❌ Загрузить MP3 файл (`files/upload` → 401)
- ❌ Настроить webhook (`settings/webhook` → 401)
- ❌ Получить список сотрудников (`users/request` → 3128)
- ❌ Воспроизвести файл в звонке (`play/start` → требует call_id из webhook)

**Причина:** Mango Office требует OAuth 2.0 для расширенных операций. OAuth не документирован для публичного API.

---

### 2. Масштабирование TTS

**Проблема:**
```
200 клиентов = 200 уникальных MP3 файлов

Каждый файл:
- Уникальное имя: "Игорь, 125 цыплят, Джанкой"
- Уникальная продукция
- Уникальная доставка
```

**Что нужно:**
1. Сгенерировать 200 MP3 через TTS (Gemini: 200 × 0.02$ = 4$)
2. Загрузить 200 MP3 в Mango (100 минут вручную)
3. Сопоставить файл с каждым звонком

**Проблема:** Загрузка файлов через API не работает. Ручная загрузка 200 файлов нереальна.

---

### 3. DTMF без webhook

**Проблема:**
- Для сбора DTMF нужен webhook URL
- Webhook настраивается только через ЛК
- Без webhook невозможно получить `call_id` активного звонка
- Без `call_id` невозможно отправить `play/start`

**Замкнутый круг:** Нет webhook → нет call_id → нет воспроизведения → нет DTMF.

## 📅 25 мая 2026 — Возвращение к play/start + aufile

**Контекст:** После развёртывания `mango_webhook.py` на VPS (работает с 24 мая) выяснилось, что play/start обрезает начало аудио. Попытка перейти на чистый baresip aufile провалилась — клиент слышал тишину.

### Что сделано

#### 1. files/upload (401)
- Загрузка WAV через VPBX API (`files/upload`) даёт 401 Unauthorized
- Сессионная авторизация через `office.mango-office.ru/auth/login` — 403 Forbidden (защита)
- **Вывод:** файл в ЛК Mango (confirm_call_kore, ID 1000550940) меняется только вручную через веб-интерфейс

#### 2. Чистый aufile (без play/start)
- `/tmp/mango_play.wav` скопирован на VPS (WAV PCM 8000 Hz, 16-bit, mono)
- baresip: `audio_source=aufile,/tmp/mango_play.wav` + `audio_player=aufile,/tmp/mango_play.wav`
- **build_confirm_audio.py:** добавлен `--with-lead-silence` (7с тишины в начале файла для baresip)
- play/start **удалён** из вебхука
- **Результат:** звонок приходит, бридж 51с / 13с, но **голоса нет** (клиент: «тишина»)

#### 3. play/start + aufile (гибрид)
- play/start **восстановлен** в вебхуке: `play_on_call()` вызывает Mango API `play/start` при Connected
- **Логи:** `result: 1000` + `events/play/start` (Mango подтверждает воспроизведение)
- **Результат:** клиент слышит **только тишину** (не play/start, не aufile)

#### 4. Корень проблемы
- `audio_player=aufile` **заменяет** входящее RTP (от play/start) содержимым файла
- Даже с коротким файлом (0.2с) — после файла aufile выдаёт тишину, play/start не проходит
- Без audio_player baresip не создаёт медиа-канал в SDP → RTP не течёт
- **Итог:** play/start (Mango API) и aufile (baresip) конфликтуют. play/start требует, чтобы baresip не потреблял входящий RTP, но без aufile baresip не согласовывает SDP.

#### 5. Текущее состояние конфигов
- **baresip:** без `audio_player`, только `audio_source=aufile,/tmp/silence.wav` (0.2с)
- **Webhook:** play/start + aufile fallback
- **WAV:** `/tmp/mango_play.wav` (31с, 7s lead silence) и `/tmp/silence.wav` (0.2с)

### Открытые вопросы

- [ ] Работает ли baresip без audio_player (SDP с audio)?
- [ ] Возможно ли загрузить WAV в ЛК Mango вручную для play/start?
- [ ] Если play/start не даёт аудио — вернуться к aufile как единственному источнику с точным lead silence
